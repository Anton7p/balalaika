# Настройка бота в @BotFather и системные кнопки Telegram

## User ID администратора бота (`TELEGRAM_ADMIN_ID`)

Один **числовой User ID** администратора Telegram-бота приложения (доступ к админ-командам в коде). Только одно значение, строкой из цифр, например: `123456789`.

Как узнать User ID:

- бот **@userinfobot** (или аналогичный), или  
- команда **`/id`** в вашем боте, если вы её добавите в код.

В GitHub Actions это секрет **`TELEGRAM_ADMIN_ID`**. То же значение при деплое подставляется в **`tgBotChatId`** встроенных уведомлений панели 3x-ui (если включены `TELEGRAM_BOT_ADMIN` и непустой id).

**Поддержка для пользователей:** опционально **`TELEGRAM_SUPPORT_URL`** (`https://t.me/ваш_аккаунт_поддержки`). Если не задан — в боте кнопка «Написать в поддержку» ведёт на `tg://user?id=` + **`TELEGRAM_ADMIN_ID`** (админ должен хотя бы раз написать боту `/start`, иначе Telegram может не открыть чат).

Секрет **`TELEGRAM_BOT_TOKEN`** — токен **бота приложения** (подписки и т.д.). Токен Telegram-уведомлений **панели** 3x-ui задаётся отдельно как **`TELEGRAM_BOT_ADMIN`** (поле `tgBotToken` в настройках панели).

## Синяя кнопка «СТАРТ» для новых пользователей

Это **не** настройка в BotFather. У пользователя, который **ещё не начинал** диалог с ботом, клиент Telegram показывает системную кнопку **«Запустить» / START** — так работает мессенджер для любых ботов.

Чтобы после нажатия всё открывалось правильно, достаточно обработать команду **`/start`** в коде бота (фото приветствия, текст, inline-клавиатура). Отдельно включать «START» в BotFather не нужно.

Кнопка **[ МЕНЮ ]** у поля ввода — это **другое**: её задаёт раздел **Menu Button** ниже.

---

## Шаг 1: Menu Button (кнопка «[ МЕНЮ ]» у поля ввода)

Соответствует константе в коде: `CHAT_MENU_BUTTON` (`src/common/content/chat-menu-button.ts`).

### Через @BotFather

1. Открой @BotFather → `/mybots`
2. Выберите бота → **Bot Settings** → **Menu Button** → **Configure menu button**
3. Тип: **Commands**
4. Текст кнопки: `[ МЕНЮ ]` (как в коде)

### Через Bot API

Подставьте токен и выполните:

```bash
curl -X POST \
  "https://api.telegram.org/bot<YOUR_BOT_TOKEN>/setChatMenuButton" \
  -H "Content-Type: application/json" \
  -d "{\"menu_button\":{\"type\":\"commands\",\"text\":\"[ МЕНЮ ]\"}}"
```

На старте приложения имеет смысл также вызывать **`setMyCommands`** из списка в коде: `DEFAULT_BOT_COMMANDS` (`src/common/content/menu-commands.ts`).

## Шаг 2: Список команд (`/setcommands` в BotFather)

Формат для вставки в BotFather (без эмодзи, описания можно написать CAPS, если так принято в вашем бренде):

```
start - ГЛАВНОЕ МЕНЮ
key - ПОЛУЧИТЬ КЛЮЧ
help - ИНСТРУКЦИИ
support - ПОДДЕРЖКА
```

В репозитории те же команды заданы как `MENU_COMMANDS` / массив `DEFAULT_BOT_COMMANDS` (описания в нормальном регистре — их видно в меню команд; при желании выровняйте текст под BotFather).

Обработчики `/key`, `/help`, `/support` нужно реализовать в модуле Telegram (или замапить на те же сцены, что и inline-кнопки).

## Целевое поведение в чате (после реализации хендлеров)

- У нового пользователя клиент показывает системную кнопку **START** до первого сообщения боту.
- После начала чата у поля ввода доступна **[ МЕНЮ ]** со списком команд.
- По **`/start`**: фото главного экрана (`resolveMainMenuPhotoPath()`), текст приветствия (`MESSAGES` / персонализация), inline-клавиатура без reply-keyboard — как в вашей архитектуре (`clean-keyboards`).
- Динамические строки («активный ключ / нет ключей», «получить / продлить») задаются в сервисе пользователя/подписки, не в BotFather.
