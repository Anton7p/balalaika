# Диагностика «нода Offline» в 3x-ui (краткий отчёт)

## Что делали

Проверили доступность панели на **master** и **ноде**, сеть master → нода и ответы **REST API** ноды при обращении с master.

## Как проверяли

1. **Ansible** (`ansible … -m shell`) по `inventory.ini`: `docker ps -a` на группах `master` и `nodes` — статус контейнера `xui_app`, порты.
2. С **master**: `curl` на ноду на порт панели (веб-страница `/panel/`) — доступность HTTP.
3. С **master** на ноду: `GET …/panel/api/server/status` с заведомо неверным заголовком `Authorization: Bearer …` — код ответа.
4. Сверка с исходниками **3x-ui v3** (`web/controller/api.go`): без валидной сессии или **Bearer API token** для `/panel/api/*` возвращается **404** (намеренно, не 401).

## Результат

- Контейнер **3x-ui** на master и на ноде был **Up**, порты в норме.
- Веб-интерфейс ноды с master открывался (**200** на `/panel/`).
- Запрос к **`/panel/api/…`** с неверным токеном давал **404** — это ожидаемое поведение панели.

**Вывод:** статус **Offline** у ноды на центральной панели чаще всего означает, что на master в записи ноды сохранён **неактуальный API token** (не совпадает с токеном на самой ноде). Тогда проба heartbeat получает **404**, и нода отображается как офлайн.

## Что сделать при повторении

- Перезапустить регистрацию нод (например плейбук `ansible/3xui/deploy-nodes.yml` / скрипт деплоя нод), **или**
- Вручную: скопировать актуальный **API Token** с ноды (Настройки → Безопасность) в карточку ноды на master.
- Если меняли **`webBasePath`** на ноде: на master в записи ноды должен совпадать **`basePath`** (в Ansible по умолчанию **`xui_node_panel_base_path`** = **`xui_web_base_path`**, см. **`ansible/3xui/defaults/main.yml`** и **`docs/PANEL_MASTER_NODES.md`**).

## Заметка по безопасности

Не храните `inventory.ini` с паролями в git; используйте секреты и `ci/ci-write-inventory.yml` (см. `docs/AGENT_INFRA.md`).
